## Producing / regenerating the export

```bash
# 1. Build the local H4 store (needs OANDA practice credentials).
#    The six majors plus NZD_USD:
set -a && source .env && set +a
python scripts/rehydrate_oanda_h4_store.py
python scripts/rehydrate_oanda_h4_store.py --instruments NZD_USD

# 2. Export each CAMPAIGN_002 H4 pair into this bundle (read-only):
for inst in EUR_USD GBP_USD USD_JPY AUD_USD USD_CAD USD_CHF NZD_USD; do
  python scripts/export_lean_parity_data.py \
      --db data/oanda_h4_research.sqlite3 --instrument "$inst" \
      --from 2020-01-01 --to 2026-05-20
done
#   → research/lean_parity/exports/campaign_002_h4/<INST>_H4_lean.csv
#   → research/lean_parity/exports/campaign_002_h4/<INST>_H4_lean.provenance.json
```

`export_lean_parity_data.py` reads only the local store — no OANDA
call, no network — and refuses any candle whose source is not
`oanda-*`. The CSV format is specified in `../../lean_h4_export_format.md`.

## Hashes / provenance

Each export writes a provenance sidecar (`*_H4_lean.provenance.json`)
carrying:

- `data_sha256` — SHA-256 over the exported candle rows; verifies the CSV;
- `campaign_002_data_request_hash` — `compute_data_request_hash(...)`
  over the same inputs the CAMPAIGN_002 artifacts recorded. **Before
  comparing a Lean run, confirm this matches the CAMPAIGN_002 artifacts**
  — that proves both engines replay the identical candles;
- `candle_count`, `first_ts`, `last_ts`, `source` (`oanda-practice`).

The provenance JSONs carry counts, timestamps, and hashes only — **no
account id, no token, no credential of any kind.**

## Fill / spread assumptions

- **Bid/ask-aware fills:** a long enters at the ask, a short at the bid.
- Fixed slippage **0.2 pips**, spread multiplier **0.5×**.
- Commission: 0.
- **Fill timing: `signal_bar_close`.** CAMPAIGN_002 predates the
  fill-timing model (`docs/research/FILL_TIMING_MODEL.md`), so the parity
  target is signal-bar-close. A `next_bar_open` parity is a separate run.
- Financing: **excluded** from parity (unmodeled in both engines).

## Known mismatch risks

| risk | mitigation |
|---|---|
| Candle timestamp alignment — OANDA H4 is 17:00-NY aligned; Lean's native FX feed is not | consume the exported CSV as custom data, preserving the open timestamps |
| Fill model — Lean's default is mid-price | configure the closest bid/ask model; treat fill price as a tolerance comparison |
| Indicator seeding / warmup | warm up 200 bars before the first entry |
| RiskEngine filters (spread / session / correlation / margin) are bespoke | excluded from parity — compare only the bespoke engine's *accepted* trades |
| Same-bar exit precedence (adverse stop first) | replicate the bespoke precedence exactly |

## Expected tolerance ranges

| quantity | tolerance |
|---|---|
| trade entry bar | same bar for ≥ 95% of trades |
| entry / exit price | within ~1 pip |
| trade count | within ±5% |
| total return | within ±0.5 percentage points |
| expectancy (R) | within ±0.03 R |
