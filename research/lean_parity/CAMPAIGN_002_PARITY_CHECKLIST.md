# CAMPAIGN_002 H4 — Lean parity checklist

A tickable checklist for whoever runs the Lean parity backtest. It
covers the **mapping** (CAMPAIGN_002 → Lean) and the **tolerances** the
result is judged against.

**This is verification, not research.** CAMPAIGN_002 is already REJECT.
A parity PASS corroborates the bespoke engine; a parity FAIL localizes a
bespoke-engine bug. Neither outcome approves a strategy.

Authoritative parameters: `research/lean_parity/lean_parity_config.json`
(generated by `scripts/build_lean_parity_config.py` from the committed
campaign config). Use it — do not hand-copy from any prose table.

## 1. Setup

- [ ] `pip install lean` (open-source CLI) and Docker Desktop running.
- [ ] `lean init` in a scratch workspace **outside** this repo's package tree.
- [ ] Read `docs/research/LEAN_PARITY_EXECUTION_GUIDE.md` end to end.

## 2. Authoritative parameters

- [ ] Regenerate `lean_parity_config.json`:
      `python scripts/build_lean_parity_config.py`.
- [ ] Confirm `_meta.source_config_hash` matches the current
      `configs/campaign_002_real_oanda.yaml`.
- [ ] Copy strategy params from the JSON: `ema_fast` 50, `ema_slow` 200,
      `donchian_lookback` 20, `atr_lookback` 14, `atr_stop_multiple`
      **2.0**, `trailing_stop_atr_multiple` **2.0**, `max_bars_in_trade`
      **240**, `min_atr_pips` **{}** (empty — no per-pair floor).
- [ ] Note: these differ from `configs/paper.yaml`'s frozen baseline
      (`atr_stop_multiple` 2.5, `max_bars_in_trade` 80). The campaign
      config is authoritative for parity.

## 3. Data

- [ ] Export real OANDA H4 candles:
      `python scripts/export_lean_parity_data.py --db <store> --instrument EUR_USD`.
- [ ] Confirm the export's `campaign_002_data_request_hash` matches the
      CAMPAIGN_002 artifacts — same candles in both engines.
- [ ] Load the exported CSV as Lean custom data, preserving the
      17:00-NY-aligned **open** timestamps (see `lean_h4_export_format.md`).
- [ ] Confirm the first and last bar timestamps match between engines.

## 4. Signal logic to replicate

On each completed H4 bar (completed bars only, no lookahead):

- [ ] Regime: EMA(50) vs EMA(200) — long-only when EMA50 > EMA200,
      short-only when EMA50 < EMA200.
- [ ] Entry: Donchian(20) breakout in the regime direction.
- [ ] Stop: hard stop at `2.0 × ATR(14)` from entry.
- [ ] Trailing stop: ratchet at `2.0 × ATR` on each completed bar.
- [ ] Time stop: exit after `240` bars.
- [ ] Same-bar exit precedence: adverse stop first, then favourable
      exit, then time stop.
- [ ] Sizing: fixed fractional, `0.25%` risk per trade, equity 500.

## 5. Cost / fill model

- [ ] Bid/ask-aware fills: long enters at ask, short at bid.
- [ ] Fixed slippage `0.2` pips, spread multiplier `0.5×`.
- [ ] Fill timing: **signal_bar_close** — CAMPAIGN_002 predates the
      next-bar-open model. (A `next_bar_open` parity is a separate run.)
- [ ] Financing: **excluded** from parity (unmodeled in both engines).
- [ ] RiskEngine spread / session / correlation / margin filters:
      **excluded** — compare only the bespoke engine's *accepted* trades.

## 6. Tolerances (pass/fail)

Compare the Lean output against the committed CAMPAIGN_002 artifacts
(`backtests/CAMPAIGN_002_REAL_OANDA_REPORT.md` and the run JSONs):

| quantity | tolerance |
|---|---|
| trade entry bar | same bar for ≥ 95% of trades |
| entry / exit price | within ~1 pip |
| trade count | within ±5% |
| total return | within ±0.5 percentage points |
| expectancy (R) | within ±0.03 R |
| verdict | both engines must read **REJECT** |

- [ ] ≥ 95% of trade entries land on the same bar.
- [ ] Trade count within ±5%.
- [ ] Total return within ±0.5 pp.
- [ ] Expectancy within ±0.03 R.
- [ ] Both engines reach the REJECT verdict.

## 7. Record the outcome

- [ ] **PASS** — log it; the bespoke engine is corroborated.
- [ ] **FAIL** — do not dismiss it. Localize the divergence (indicator
      seeding, fill model, stop precedence, timestamp alignment) and
      treat it as a bespoke-engine bug to fix, then re-run.
- [ ] Record every divergence in `src/forex_bot/lean/parity_notes.md`.
- [ ] A parity result **never** approves a strategy — it validates the
      measurement instrument only.
