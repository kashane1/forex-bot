## 1. Selection

**First campaign:** `CAMPAIGN_002` — H4
`trend_following 0.1.0-baseline-frozen`.

### Why CAMPAIGN_002, not CAMPAIGN_011

The plan (`INFRA_BACKTRADER_SECONDARY_LANE_001_PLAN.md` §6) outlined two
candidates: CAMPAIGN_002 (best-documented, has Lean mapping spec, has
the no-RiskEngine bespoke reference JSON ready to compare against) and
CAMPAIGN_011 (deterministic by seed, minimal indicator surface, but
no-RiskEngine reference does not exist for this campaign).

CAMPAIGN_002 wins on **comparison ergonomics**:

1. **Bespoke reference is a single file:**
   `research/lean_parity/campaign_002_h4_bespoke_reference.json` —
   one full-window run, 1,647 trades, per-pair expectancy / return /
   profit factor / win rate / drawdown. The Phase 5 comparison harness
   reads this single file.
2. **Mapping spec is authoritative:**
   `docs/research/CAMPAIGN_002_LEAN_MAPPING_SPEC.md` pins every rule,
   indicator definition, fill behaviour, sizing formula, and known
   approximation in one place. The Backtrader port is a near-mechanical
   transliteration.
3. **Lean parity config is committed:**
   `research/lean_parity/lean_parity_config.json` — generated by
   `scripts/build_lean_parity_config.py` from the original
   `configs/campaign_002_real_oanda.yaml`. The adapter reads strategy
   parameters from this file (not hard-coded), so any drift in the
   config surfaces as a clear test failure.
4. **Existing local cross-reference:**
   `research/parity_verifier/` already implements CAMPAIGN_002 rules in
   independent Python — when the Backtrader lane disagrees with bespoke,
   we can cross-check against the parity_verifier lane to localise the
   divergence to Backtrader-specific behaviour rather than rule-port
   error.

CAMPAIGN_011's per-bar SHA-256 coin-flip is itself a downstream check
that becomes interesting *after* the engine baseline is established —
which is what CAMPAIGN_002 is for. (CAMPAIGN_011 is a candidate for
Phase 7.)

## 2. Frozen rules implemented (from the mapping spec)

| spec § | rule | implementation |
|---|---|---|
| §3 | EMA(50), EMA(200) | `bt.indicators.ExponentialMovingAverage(period=50/200)` — same α, same `EMA[0]=close[0]` seeding as pandas `ewm(adjust=False, min_periods=L)` |
| §3 | ATR(14) Wilder | `bt.indicators.AverageTrueRange(period=14)` — Backtrader's default smoothing is Wilder's |
| §3 | Donchian-20 prior bars only | manual `deque(maxlen=20)` of completed-bar highs/lows; updated **after** each `next()` call so bar `t` reads `t-20..t-1` |
| §4.1 | trend regime: EMA50 vs EMA200 | direct comparison on bar `t` |
| §4.2 | breakout: close[t] > donchian_high (long) or < donchian_low (short) | direct comparison on bar `t` mid close |
| §4.3 | volatility floor | `min_atr_pips` from config (empty `{}` for CAMPAIGN_002) — gate disabled |
| §4.4 | ADX gate | `adx_min` is null in the frozen baseline — gate disabled |
| §4.5 | one position per instrument | strategy maintains internal `_in_position` flag |
| §5.1 | trailing stop ratchet on every bar | long: `bid_close - 2.0×ATR`; short: `ask_close + 2.0×ATR`; raise-only / lower-only |
| §5.2 | adverse stop check (first in exit ladder) | long exits if `bid_low ≤ stop`; short exits if `ask_high ≥ stop` — exit price = stop price |
| §5.2 | time stop (second) | exits at `bars_held ≥ 240` — exit price = `bid_close` (long) / `ask_close` (short) |
| §5.2 | end-of-data (third) | last-bar open position closes at `bid_close` / `ask_close`, reason `eod` |
| §6 | sizing: 0.25%-of-equity, whole units | manual `_size_position(...)` using current NAV, USD-quote / USD-base pip-value rules |
| §6 | NAV compounds at trade close | strategy increments `nav["value"]` after each closed trade |
| §7 | bid/ask-aware fills at signal_bar_close | manual `_fill_entry_price(...)`: long uses ask + max(0.2, spread×0.5); short uses bid − max(0.2, spread×0.5) |
| initial stop | anchored at bar **mid close**, rounded to instrument display precision | `_round_price(...)`, then carried through sizing |

## 3. Rules approximated

These follow `BACKTRADER_RUNNER_CONTRACT.md` §6 and are surfaced in the
adapter's `approximation_flags`:

| flag | meaning |
|---|---|
| `BACKTRADER_INDICATORS` | EMA + ATR come from Backtrader; early-warmup seeding *should* match pandas but float-precision differences in the first few hundred bars are expected |
| `DONCHIAN_PRIOR_BARS_ONLY` | manual deque (Backtrader's stock `Highest`/`Lowest` includes the current bar — that would be a look-ahead) |
| `BACKTRADER_BROKER_BYPASSED` | the Cerebro broker is **not** used for fills; the strategy maintains its own position state machine, fills at `signal_bar_close` exactly per the bespoke convention |
| `MANUAL_SIZING_RISK_FRACTION` | `_size_position(...)` does the whole-unit floor; sub-bps drift versus bespoke from Decimal-vs-float precision is expected |
| `TRAILING_STOP_RATCHET` | per spec §5: same 2.0×ATR multiple; bid_close for long, ask_close for short |
| `NO_RISK_ENGINE` | spread / session / loss-limit gates not applied (matches the no-RiskEngine bespoke reference at 1,647 trades) |
| `NO_FINANCING` | financing/swap not modeled; comparison is pre-financing only |

Plus the data-adapter flags inherited from `BACKTRADER_DATA_ADAPTER_SPEC.md`:

| flag | meaning |
|---|---|
| `MID_OHLC_DERIVED` | Backtrader sees mid OHLC; bid/ask carried on extra lines |
| `BAR_OPEN_TIMESTAMP` | index value is the bar OPEN time (17:00-NY-aligned) |
| `HALF_SPREAD_CLOSE` | per-bar half-spread carried at bar close only |

## 4. Unsupported features (deliberately out of scope)

- **RiskEngine gates.** Spread / session / loss-limit / exposure gates
  are NOT modelled. The comparison target is the 1,647-trade
  no-RiskEngine reference, not the 1,032-trade with-RiskEngine
  reference.
- **Multi-instrument shared equity.** The runner drives each pair in a
  separate Cerebro with the campaign's default starting equity. This
  matches the bespoke per-pair convention and the parity_verifier lane.
- **Financing / swap.** Not modelled in either engine for this
  campaign. Comparison runs pre-financing only.
- **D1 / H1 timeframes.** Out of scope. Only H4.
- **ADX gate (CAMPAIGN_003).** Not enabled in the frozen 0.1.0 config.
